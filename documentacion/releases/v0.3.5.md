# v0.3.5 — Endurecimiento de seguridad HTTP en Cloudflare Worker

## Issue #19
- Mismo conjunto de cabeceras de seguridad para la API, HTML, recursos estáticos y errores: CSP, X-Content-Type-Options, Referrer-Policy, X-Frame-Options y Permissions-Policy.
- HSTS se envía solo sobre HTTPS. La CSP restringe scripts, estilos, conexiones y fuentes al mismo origen; impide inserción de frames, objetos y cambios de base URI.
- Las rutas API mantienen el catálogo sintético y la salud; solo GET y HEAD están permitidos en esos endpoints, con respuesta 405 y Allow cuando corresponde. La votación permanece deshabilitada (503 para todos los métodos).
- Política de caché explícita: `no-store` para API y errores; `no-cache` para HTML y assets sin versión; `immutable` para recursos con hash identificable de esbuild.
- Pruebas Node de todos los casos anteriores; CI y QA visual de Chromium.

## Límites
- No añade endpoints nuevos, votos reales, persistencia, migraciones ni dependencias.
- La configuración de `wrangler.jsonc` conserva `run_worker_first: true`; las cabeceras se aplican también a las respuestas de recursos servidos mediante ASSETS.
- El comportamiento de Cloudflare en producción (incluidos cache/CDN, cabeceras y reglas externas) aún debe comprobarse externamente después de cualquier despliegue aprobado. Estas pruebas verifican el código del Worker, no la configuración de la cuenta.
