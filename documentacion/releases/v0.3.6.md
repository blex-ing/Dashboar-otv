# v0.3.6 — Calidad, accesibilidad y mediciones reproducibles

## Issue #20
- Casos negativos del validador de catálogo: límites, campos ausentes, referencias inválidas, payload malformado, respuesta HTTP errónea y aborto de peticiones.
- Nuevas pruebas visuales de accesibilidad básica por vista (seis vistas): landmarks, etiquetas, nombres accesibles, heading principal, IDs únicos y enlace de salto; teclado y foco en pantalla de 320 px.
- Script `npm run quality:metrics` que produce JSON con tamaños reales JS/CSS sin comprimir y gzip, benchmark sintético (mediana, p95, 300 repeticiones) e indicadores léxicos de decisiones por archivo.
- GitHub Actions adjunta los resultados de métricas y el informe visual durante 14 días; no se han inventado valores ni umbrales de rendimiento.

## Restricciones y honestidad metodológica
- **Los indicadores léxicos NO son complejidad ciclomática o cognitiva formal**. TypeScript 7 no expone aún la API JS clásica de análisis de AST; el método de medición se documenta y el análisis formal queda pendiente.
- Las pruebas de accesibilidad no son una certificación WCAG, ni sustituyen contraste, ampliación, lector de pantalla o inspección manual.
- El benchmark es en memoria con catálogo sintético, no mide tiempo real en la red ni usuarios simultáneos.
- Sin nuevas dependencias, cambios visuales, votación real o migraciones de base de datos.
