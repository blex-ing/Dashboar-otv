# v0.3.1 — Validación robusta de catálogo remoto

## Correcciones
- **#15**: validación en tiempo de ejecución de la respuesta JSON de `/api/public/catalog`: campos obligatorios, identificadores únicos, candidatos, propuestas, afirmaciones, fuentes y entrevistas.
- Rechazo de relaciones huérfanas, números no finitos/negativos, enlaces con esquemas inseguros y tiempos que excedan la duración de entrevistas.
- Límite de 1 MB de respuesta antes de procesar el JSON, con error controlado.
- Ante API inválida o no disponible, se informa y se vuelve al catálogo sintético; sin guardar preferencias ni votos.
- Nuevos tests Node de integridad del contrato, payload inválido y límite; test Playwright de fallback ante catálogo corrupto.

## Compatibilidad y restricciones
- Sin dependencias adicionales, cambios de base de datos ni apertura de endpoints de escritura.
- No incorpora datos reales ni nuevas ediciones; sigue siendo exclusivamente una demostración de Otavalo e Ibarra.
- Versiones sincronizadas en `web/package.json`, `web/package-lock.json`, Worker health y footer.
